# Roadmap

**Purpose**: what to build next, in what order, and how you'll know a step is actually done.

**Ownership**: whole team — this should reflect reality, not just the original plan. Update status as steps complete (see the root README's Status section, which should always match this).

**Contents**:
- `build-plan.md` — the full 16-step, priority-ranked (P0→P3) build order, with a "definition of done" per step and a suggested team split.

**Convention**: don't reorder or renumber steps casually — if priorities genuinely change, note it as a decision in `docs/decisions/`, since the numbering is referenced elsewhere (issues, PR titles, this doc).
